# Gantry 1.0.0-rc.2 acceptance record

Status on 2026-10-04: [published prerelease](https://github.com/utrost/Gantry/releases/tag/v1.0.0-rc.2), with Linux x64 DEB and Windows x64 MSI.
Implementation: [PR #28](https://github.com/utrost/Gantry/pull/28).
Released application/packaging revision: `c1c05fc`.
Tagged [release CI](https://github.com/utrost/Gantry/actions/runs/37213208083) passed on both platforms; all downloaded asset SHA-256 checksums were verified before publication.

## Automated evidence

- **471 Java tests passed**, zero failures/errors/skips, in the local clean
  Java 17 build and platform builds. Separate
  [Java 17/21 CI](https://github.com/utrost/Gantry/actions/runs/36264126413) passed.
- **Nine Python packaging regression tests passed** on both CI platforms.
- [Native installer CI](https://github.com/utrost/Gantry/actions/runs/36264126415)
  passed on Ubuntu 22.04 and Windows Server 2022, including installation,
  upgrade, bundled-Java GUI launch and uninstall.

| Check | Ubuntu 22.04 CI | Windows Server 2022 CI | Ubuntu 24.04 local |
|---|---|---|---|
| Eight installed-runtime workflow checks | Passed before/after upgrade | Passed before/after upgrade | Passed with CI-built package |

| Settings/history/recovery/project hashes | Preserved through upgrade/uninstall | Preserved through upgrade/uninstall | Preserved across launches |

The eight service-level checks cover settings, project/recovery, history, SVG
import, mock plot completion, cancellation with pen raised, G-code export, and
PNG centerline vectorization/import. Only mock and file backends are used.
The command refuses to seed a nonempty profile. Tests also check corrupted-state
detection, legacy state migration, and isolation of explicit profiles.

GUI/CLI JAR manifests report `1.0.0-rc.2`; CLI help and staged asset SHA-256
verification passed. Persisted hashes and Java totals were independently checked
against downloaded CI evidence. Use the CI Ubuntu 22.04 package for distribution;
a locally built Ubuntu 24.04 DEB has a newer library baseline.

The older installer is a **synthetic fixture**: current code with an older version
identity. This validates package replacement and state preservation, not all
historical application-schema compatibility. Existing public RC1 assets remain
unchanged. Validation reports/logs are attached to the native CI run as
`validation-ubuntu-22.04` and `validation-windows-2022` artifacts.

## Windows package contents and download checks

The MSI now installs for the current user with GUI, native CLI, bundled Java 21,
offline HTML help and screenshots, four SVG samples, license and version files.
Windows Installer's product API reported exactly one candidate with context `2`
(per-user unmanaged) and native version `1.0.2`. The GUI and Help shortcuts were
present in the current user's Start menu; the CLI had no Start menu shortcut.

Native payload checks passed on both platforms: every local guide link resolves,
all images/samples/license/version files are present, the native CLI returns help
and imports an included SVG with system Java removed from PATH, and the Help
launcher resolves the installed guide from another working directory.

Windows, Linux and portable CI downloads were independently downloaded and
checked against their own SHA256SUMS. Installer artifacts contain the platform
package plus standalone README, license and version files. Portable artifacts
contain both JARs and a complete docs ZIP. The README has no local image or
repository-documentation links. Full ZIP extraction retains all offline links.
Verified assets are also staged locally under `dist/1.0.0-rc.2/`.

See [installer contents and paths](../docs/packaging/README.md). PATH is not changed
automatically. The native upgrade fixture now tests per-user-to-per-user scope;
migration from earlier unpublished machine-wide CI installers is not claimed.
