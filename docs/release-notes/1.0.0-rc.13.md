# Gantry 1.0.0-rc.13

Testing prerelease for Windows x64, Linux x64 and portable Java. This is a new
immutable candidate containing the fixes made after RC11 and the held RC12 draft.
It is not a stable or hardware-accepted release. RC12 and earlier assets are unchanged.

## Artwork and machine coordinates

- Fresh profiles use versioned upright artwork coordinates, with consistent
  workspace, SVG and heatmap orientation. Existing unversioned profiles keep
  their calibrated mapping and G-code. Migration requires disconnection, explicit
  review and fresh pen-up direction/frame checks; no automatic migration occurs.
- Complete first strokes and controller-space starts now appear in preview and
  hit testing, including known refill/rinse stations and excluded first layers.
- A DRAW without an initial MOVE is rejected when the backend reports a non-origin
  or nonfinite start. Gantry does not add an automatic positioning move. When the
  backend cannot report position, the legacy origin assumption is logged; verify
  the start physically before plotting.
- Time estimates now follow the actual prepared plot route, including first
  segments, clipping, station travel, parking, lift timing and dwell. Speed
  overrides scale motion without scaling fixed dwell/settle times. These remain
  planning estimates, without physical firmware/acceleration calibration.

## Included since the last public candidate (RC11)

- Editable quick text/shapes, reviewed SVG/ZIP export, reusable named pens and
  advisory ink-overlap review.
- Mock Stop/recovery and scripted serial/backend contract regressions.
- Squiggle quality fixes with visual/cost evidence, packaged PNG support,
  reproducible saved image-art recipes, consistent overrides and reliable batch
  failure/collision/source protection. FOP remains optional and unbundled.
- Refreshed user/developer guides, all 47 application screenshots, a one-minute
  mock walkthrough and offline documentation link checks in CI.

## Downloads and validation

Windows MSI and Linux DEB include Java and offline help. Portable GUI/CLI JARs
require Java 17 or newer. Native installer identity is `1.0.13`; Windows installers
are unsigned. Use SHA256SUMS to verify the eight payload assets. The ninth asset
is SHA256SUMS itself.

The software baseline passed 623 Java and 12 Python tests, Swing mock workflows,
128 controller-start cases, 512 orientation renderings and 256 unchanged legacy
G-code hashes. Candidate-specific Java 17/21 and Windows/Linux install, upgrade,
bundled-runtime launch and uninstall results are recorded in the
[candidate evidence](https://github.com/utrost/Gantry/blob/main/docs/release-results/1.0.0-rc.13.md).
Upgrade CI uses current code with a synthetic RC11 installer identity; it does
not establish migration from every historical schema or real user installation.

## Remaining acceptance

Physical direction/frame/plot checks for #93, Windows 11/iDraw Stop/recovery #39,
actual native scaling #43, operator/expert benchmark #54, a real artwork task #72
and the five-person novice study #16 remain open. Mock and scripted serial tests
do not establish firmware or physical fidelity. The
[RC13 operator worksheet](https://github.com/utrost/Gantry/blob/main/docs/release-results/1.0.0-rc.13-operator.md)
starts with every external acceptance row NOT RUN. Begin with the disconnected
mock guide; review coordinate compatibility before connecting an existing setup.
