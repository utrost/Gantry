# Gantry 1.0.0-rc.14

Testing prerelease for Windows x64, Linux x64 and portable Java. Includes all
post-RC13 fixes and #111–#115. Older tags and assets remain unchanged, including
the held RC12 draft. Physical and human acceptance remain open.

## Changes since RC13

- Correct watercolor refill geometry/accounting, rinse-pot colour mapping,
  station nudges and homing fault waits (#106–#109).
- Wait for a production GRBL planner-completion barrier and fresh Idle before
  pen handoff or final success. Stop, alarm, disconnect and timeout prevent false
  success (#111).
- Select a serial GRBL simulator under Settings → Simulation. It exercises the
  production backend over an in-memory transport without opening a real port;
  the lightweight mock remains available (#112).
- Review read-only firmware travel/feed limits, report units and work origin
  before GUI GRBL XY motion. Explicit machine-coordinate ranges intersect the
  existing profile without enlarging it. Missing limits, excessive feeds and
  unreviewed reference changes block motion; whole routes and stations are checked (#113).
- Choose any of nine placement references. Numeric position, resizing, rotation
  and mirroring retain the chosen point; save/reopen, recovery and Undo/Redo
  preserve it. An edit that cannot fit while retaining the point is rejected (#114).
- Review a persisted pen-only partial restart or reverse traversal, with exact
  layer/command/pass selection and immutable source identity. Uncertain ink stays
  uncertain after Stop or process loss. Three explicit confirmations and fresh
  machine review are required; preparing a proposal never starts motion. Watercolor
  restart is blocked pending a separate loading/cleaning policy (#115).

## Downloads and validation

Windows MSI and Linux DEB bundle Java and offline help. Portable GUI/CLI JARs
require Java 17 or newer. Native installer identity is `1.0.14`; Windows installers
are unsigned. SHA256SUMS covers the other eight release assets.

The software baseline passes 682 Java and 12 Python tests, with Swing simulation,
two-process restart, layout and compatibility coverage. Candidate-specific builds,
installer upgrade reports and independently downloaded checksums are recorded in
[RC14 evidence](https://github.com/utrost/Gantry/blob/main/docs/release-results/1.0.0-rc.14.md).
Upgrade CI uses current code with synthetic RC13 identity; it does not establish
compatibility with every historical application or profile schema.

## Remaining acceptance

Firmware simulation does not establish physical fidelity. Direction/frame/plot
#93, Windows 11/iDraw Stop/recovery #39, native scaling #43, operator/expert #54,
real artwork task #72 and five-person novice study #16 remain open. Use the
[RC14 worksheet](https://github.com/utrost/Gantry/blob/main/docs/release-results/1.0.0-rc.14-operator.md)
and record exact artifact identity. Automatic physical resume and watercolor
restart remain unsupported. This candidate is not a stable-readiness claim.
